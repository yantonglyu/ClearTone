# 澄音：保持简单，逐步成为完整的个人播放器

更新于 2026-10-23，面向 0.2.0 之后的工作。源码中已存在的功能、已经完成的验证和未来计划分别记录，原型可运行不代表所有设备和来源都已验收。实际发布状态以 GitHub Releases 为准。

## 产品方向

一个打开就能听歌、想唱就能练习、学习时安静陪伴的 Windows 原生播放器。优先满足清楚的个人需求，同时提供可安装、可理解、可贡献的开源版本。

网易云、B 站和本地文件共享音乐库与播放队列。视频是播放页的另一种呈现。专注计时在所有页面使用同一份会话，休息不计入累计学习，结束后清零本次计时。更多来源逐一接入，避免把每个平台完整复制成新的导航层级。

视觉继续使用封面配色、透明图标、暖色品牌、柔和歌词与少量轻量动效。可爱来自一致的形状、颜色和细节，关键操作一两步完成。高级功能放在音频详情或上下文菜单里，不堆出难以学习的设置树。

## 接下来的顺序

### 1. 先稳定媒体通路

优先处理视频播放、拖动同步、网络中断、链接过期、音频设备拔插及关闭时资源回收。普通音乐、视频和可选后台分析分别测量，避免修好一个场景却让另外一个保持无效解码或轮询。

下一项架构实验是**将媒体解码放入独立工作进程**。界面、学习记录和音乐库仍由主进程持有，通过小而明确的协议交换播放状态。工作进程崩溃时，主窗口应保持响应，能够重建媒体会话并提示重试。这是未来实验，当前没有完成进程隔离，也不能声称现有播放器已消除解码崩溃。

先比较 Windows 媒体通路的覆盖和恢复能力，再评估 libmpv / FFmpeg 等备选。候选后端必须同时核对许可证、包体积、硬件解码、代理请求、格式范围和可维护性。不为引入后端重写整个 UI、账号系统和计时逻辑。

退出条件：代表性网易云歌曲、B 站分 P、MV、本地文件完成播放/暂停/跳转/切换/结束测试。模拟网络与解码失败后，窗口、计时和已有记录可恢复。完整回归记录通过后，才替换默认后端。

### 2. 把性能变成可重复的验证

固定窗口大小、缩放、音量、缓存和电源状态，同一机器至少进行三轮比较。分别记录全部相关进程的 CPU、Private Bytes、工作集、GPU 和解码活动。

| 场景 | 验证方法 |
| --- | --- |
| 暂停与最小化 | 预热后采样 5 分钟，确认没有无效动画和隐藏视频解码 |
| 普通歌词播放 | 同一素材采样 5 分钟，比较基线 CPU、内存与可闻掉音 |
| 视频播放 | 按编码、分辨率和帧率区分样本，单独报告硬解状态 |
| 页面与歌单 | 分页、虚拟化、快速切页和过期请求，不让旧结果覆盖新查询 |
| 连续播放 | 30 分钟连续播放，1 小时观察内存和句柄趋势 |
| 人声分析 | 独立报告峰值与等待时间，限制并发，前台播放优先 |

先移除后台无效工作，再处理热点。保留封面缓存上限和请求合并，避免每帧重新模糊或提取颜色。不把“原生”当作低占用证据，不在缺少测量时承诺百分比。

### 3. 统一来源与资料库

逐步规范来源标识、查询分页、播放解析、歌词、歌单和能力声明。界面只展示来源真正支持的动作，例如 B 站条目不能被写入网易云歌单，也不能按网易云歌曲上报听歌记录。

后续增加混合歌单导入导出、来源失效提示和录音版本候选。歌曲匹配需要区分录音室版、现场版、翻唱、伴奏及不同剪辑，优先保留用户选择，不凭同名自动替换。

若 JSON 的规模确实成为瓶颈再考虑 SQLite。迁移先备份、复制、校验，然后切换。重复导入同一份学习记录不能叠加总时长。

退出条件：分页歌曲完整、收藏与队列身份稳定、账号切换清晰，导出不包含 Cookie、音频文件或私人收听账本。每个新来源独立完成错误处理和退出登录测试。

### 4. 更好用的跟唱练习

先完善读音与时间对齐，再加功能。专有名词、当て字、人名、长音和中日混排继续允许人工纠错。平台逐字时间与实际音源不一致时可校正，只有句级时间时明确保留估算性质。

第二阶段加入本地录音、回放与 A/B 对照，麦克风默认关闭，录音留在本机。之后才评估音高轨迹辅助。不用目前会漏检、跳八度或残留伴奏的音高估计给唱功评分。

Utatomo 的公开介绍提供了原文与读音对应、读音可纠错等交互参考。未取得并确认可复用许可的代码、词典或素材不直接复制。英语 IPA 和更多语言作为后续可选能力，日语日常使用优先。

退出条件：代表性日语曲目人工检查、纠错可撤销、连续跟随不中断、循环/变速不影响真实听歌与学习时长。

### 5. 简单但诚实的 Hi-Fi

日常共享输出保持默认。常用 EQ、音量均衡和输出设备容易找到，处理链状态真实可见。无缝切歌和格式切换是下一步常用能力。

高级的“原样输出”需要独立验证未处理通路、格式协商、整数位深和真实 DAC。独占模式不自动等于 bit-perfect，也不自动提升音质。DSD→PCM、原生 DSD 和 DoP 分别验收，未经设备确认不能把 DoP 数据发往普通 PCM 输出。原生 DSD/DoP 尚未实现。

最终希望用户只需在日常播放、原样输出和跟唱练习之间作少量选择，专业细节按需展开。这三个简化方案仍是设计目标，不能用菜单文案代替底层实现。

## 每次交付的约束

修改前备份当前程序与数据。先在隔离目录验证，不能用开发者账号和学习记录制作测试包。安装器使用新构建的清洁文件清单，个人数据和模型分开放置。

每次记录概念、原型、评估和实现状态。计划没有完成前不标记已实现，已实现没有经过相应测试前不标记已验收。发生播放或记录回归时保留可回滚版本，修复并重新验证后再发布。

Scheduling 为 N/A，当前工作按用户要求推进，没有定时任务。Monitoring 使用手动回归、隔离诊断和本地错误日志，没有另建持续遥测或定期自动化。
